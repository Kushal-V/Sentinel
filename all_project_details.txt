SENTINEL: Master Project SpecificationCore

Identity: A deterministic, multi-tenant Supply Chain Digital Twin powered by an autonomously governed multi-agent AI workforce.

Pillar 1: The Multi-Tenant User Interface (Streamlit Frontend)The interface is the command center where the human operator oversees the AI network. It is built to adapt to any industry on the fly.Dynamic File Uploader: Users can upload any CSV file (e.g., Hospital Beds, Shipping Fleet, Retail Apparel). The system does not rely on hardcoded "toy factory" columns; it ingests the data and dynamically adapts its entire interface to the new industry.Live Data Dashboard: A real-time tabular view of the active state (the "Master Clipboard"). If the AI changes a value, the UI updates instantly.The Crisis Console: A chat-based interface where the user triggers disruptions (or types custom queries). It streams the agents' internal thought processes, tool executions, and Sandbox rejections live on the screen.Human-in-the-Loop (HITL) Gate: The AI is strictly forbidden from executing state changes autonomously. When the AI finalizes a safe plan, the UI renders an "Approve & Execute" button. The human operator holds the final key.Trust Score Visualizer: Animated progress bars in the sidebar showing the real-time "Trust Score" (0.0 to 1.0) of each specialist agent, allowing the user to see the AI's internal governance at a glance.

Pillar 2: The Deterministic Data Core (Pandas Engine)LLMs hallucinate, so Sentinel separates reasoning from state. The agents hold no memory of the inventory; they must read and write to a strict Python backend.The State Manager: A thread-safe Python class that manages inventory.csv (current state) and transaction_log.csv (historical ledger). It handles all file I/O operations and locks the data during writes to prevent corruption.Dynamic Schema Inferencer: The statistical brain of the data layer. When a new CSV is uploaded, it uses regex and statistical profiling (checking if column_A <= column_B in >75% of rows) to automatically detect "Constraint Pairs." It figures out that currently_admitted is physically bounded by max_bed_capacity without human programming.

Pillar 3: The Shadow Sandbox (Patent Claim A)This is the protective middleware that guarantees the AI cannot break the physical laws of the business.The Deep Clone: Before an agent's proposed action is executed, the Sandbox creates a temporary, isolated, in-memory copy of the entire dataset.Mathematical Assertion Engine: The Sandbox applies the agent's proposed change (e.g., adding 500 units) to the cloned data. It then checks the math against the rules found by the Schema Inferencer. It asserts that the new value is $\ge 0$ and $\le$ the dynamic maximum limit.The Feedback Loop: If the math fails (e.g., the agent tries to overflow a warehouse), the Sandbox blocks the action, rolls back the clone, and returns a strict, highly detailed text error back to the LLM (e.g., "Constraint Violation: Target column exceeds max_capacity by 250 units"). The LLM reads this and recalculates.

Pillar 4: The Agentic Workforce (Hybrid Architecture)Sentinel uses a specialized, cost-optimized mix of different AI models via LangChain, routing tasks to the models best suited for them.The Dispatcher: The receptionist. It does not solve problems. It takes the user's crisis input, analyzes it, and outputs a strict Pydantic JSON schema to route the task to the correct specialist. It is extremely fast and cheap.The Specialists: The problem solvers. Because they run on Groq LPUs, they have near-zero latency. They use LangChain Data Tools to read the schema, query the state, and propose changes.The Maker: Optimizes production and machine lines.The Mover: Optimizes logistics, routes, and transit times.The Keeper: Optimizes warehouse storage and inventory constraints.The Analyst: The auditor. It has a massive context window to read thousands of rows of the transaction_log.csv and evaluate the physical/financial success of past agent decisions.

Pillar 5: Retrospective Authority Weighting (Patent Claim B)This is the autonomous governance loop that forces the AI network to learn from physical business metrics, not just semantic chat feedback.ROI Evaluation: The Analyst agent periodically audits the ledger. It looks at past mitigation plans and calculates their real-world impact (e.g., Did The Mover's decision to use air freight prevent a stockout, or did it just waste budget?).Trust Score Penalty: If an agent's past decisions were mathematically detrimental, or if it repeatedly tried to break the Sandbox physics, the Analyst lowers that agent's trust score in the agent_trust_scores.json file.The Dispatcher Override: Before the Dispatcher routes a new crisis, a Python script checks the target agent's trust score. If the score has dropped below the critical threshold (e.g., 0.50), the system overrides the LLM's choice, flashes a warning on the UI, and forces the task to a safer fallback agent.

Pillar 6: The Testing & Simulation EngineTo prove the system works, Sentinel includes built-in stress-testing mechanisms.Mock Event Generator: A sidebar dropdown containing structured JSON payloads for crises (e.g., Port Strikes, Machine Breakdowns, Demand Spikes) that instantly inject chaos into the system.Faker Data Pipeline: An automated script (generate_test_data.py) that uses the faker library to generate highly realistic, massive CSV datasets for completely different industries (Server Farms, Global Shipping fleets) to prove the Schema Inferencer works anywhere.
